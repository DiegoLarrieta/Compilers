1. Cubo semántico

El cubo semántico responde una pregunta: si se aplica un operador a un operando de un tipo y otro de otro tipo, ¿de qué tipo es el resultado, o es un error? BabyDuck tiene dos tipos declarables (int y float) y un tercero, bool, que solo existe como resultado de una comparación.

Decisiones de diseño

  • Si participa un float, el resultado es float. Es la promoción usual: no se pierde información.
  • int / int da int (división entera, como en C). Para obtener decimales basta que un operando sea flotante: total / 2.0.
  • Las comparaciones dan bool y un bool no se puede volver a operar ni asignar. No hay variables bool; el tipo existe para validar la condición de if y while.
  • Asignación: a una variable float se le puede asignar un int. A una variable int no se le puede asignar un float, porque se perdería la parte decimal sin avisar.

Implementación: cubo_semantico.py

El cubo es un diccionario de tres niveles: CUBO[operador][tipo_izquierdo][tipo_derecho]. Se eligió así porque la consulta es directa (tres búsquedas en tablas hash, costo constante) y porque el código se lee igual que la tabla de arriba. Las combinaciones inválidas se guardan explícitamente como "error", así que ninguna consulta falla por llave inexistente.

tipo_resultante("+", "int", "float")   # -> "float"
tipo_resultante(">", "int", "int")     # -> "bool"
tipo_resultante("=", "int", "float")   # -> "error"

Qué estructura se eligió y por qué

SituaciónEstructuraPor qué
Directorio de funcionesTabla hash (dict)
nombre → Funcion		La operación más frecuente es buscar por nombre: "¿ya existe esta función?", "¿existe la función que se quiere llamar?". En un dict cuesta O(1) en promedio; en una lista costaría O(n). Los nombres son únicos, igual que las llaves.
Tabla de variables de un alcanceTabla hash (dict)
nombre → Variable		Mismo motivo: cada uso de una variable en el programa es una búsqueda por nombre. Además, detectar una variable doblemente declarada es solo preguntar si la llave ya existe.

Una tabla por función (no una sola tabla para todo)Tablas separadasDos funciones pueden tener variables con el mismo nombre sin chocar, y una local puede tapar a una global.

Un punto neurálgico es un lugar de la gramática donde, además de reconocer la sintaxis, se ejecuta una acción. Aquí las acciones crean y llenan el directorio y las tablas. Los diagramas muestran dónde cae cada punto; solo aparecen los diagramas que tienen alguno.

Cómo se pone un punto neurálgico en PLY

Al final de una regla: es el código de la función de esa regla. PLY lo ejecuta cuando termina de reconocerla. El punto 2 es así:

def p_decl(p):
    """decl : lista_ids COLON tipo SEMICOLON"""
    for nombre, linea in p[1]:                       # p[1] = lista de ids, p[3] = tipo
        directorio.agregar_variable(nombre, p[3], linea)

A la mitad de una regla: se inserta un no terminal vacío (todos se llaman np_*). Como no consume tokens, PLY ejecuta su función justo en ese lugar. Dentro de ella, p[-1] es el símbolo anterior. El punto 3 es así:

def p_func(p):
    """func : VOID ID np_crear_funcion LPAREN params_opt RPAREN LBRACKET vars_opt body RBRACKET np_cerrar_funcion SEMICOLON"""

def p_np_crear_funcion(p):
    """np_crear_funcion :"""
    directorio.crear_funcion(p[-1], linea_del_anterior(p))    # p[-1] = el ID de la función

El punto 3 tiene que ir a la mitad: la función debe existir en el directorio antes de leer sus parámetros y variables, porque esos van a su tabla.

Casos que sí se permiten, y que también están probados:

  • Una variable local con el mismo nombre que una global. Dentro de la función, la local tapa a la global.
  • Dos funciones distintas con variables o parámetros del mismo nombre.
  • Una función que se llama a sí misma (ya está en el directorio cuando se compila su cuerpo).

Una función solo puede llamar a funciones declaradas antes que ella, porque el directorio se llena en una sola pasada.
