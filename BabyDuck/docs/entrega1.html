Herramienta seleccionada: PLY

  • Conecta con Python sin pasos extra. El scanner y el parser son módulos normales de Python; se corren y se depuran igual que el resto del código.
  • Las entregas siguientes piden puntos neurálgicos. PLY permite ejecutar código al terminar una regla o a la mitad de ella. Con Lark o con los visitors de ANTLR habría que recorrer un árbol después.
  • Es el mismo modelo de la tarea previa. Lo aprendido con flex/bison (tokens, reglas BNF, conflictos shift/reduce) aplica directo.
  • Buena documentación. El manual oficial cubre lex y yacc con ejemplos completos.

El costo que se acepta: la gramática se escribe en BNF puro, y la versión queda fija en ply==3.11 (ver requirements.txt).

2. Cómo se dieron de alta las reglas

Scanner: lexer.py

PLY lee tres cosas del módulo: la lista tokens, las variables t_NOMBRE (expresión regular de un token simple) y las funciones t_NOMBRE (expresión regular en el docstring más una acción).

tokens = ["ID", "CTE_INT", "CTE_FLOAT", "CTE_STRING", "PLUS", ...] + list(palabras_reservadas.values())

t_PLUS = r"\+"          # token simple: solo su expresión regular
t_NE   = r"!="

def t_CTE_FLOAT(t):     # token con acción: convierte el lexema a número
    r"\d+\.\d+"
    t.value = float(t.value)
    return t

def t_ID(t):
    r"[A-Za-z_][A-Za-z0-9_]*"
    t.type = palabras_reservadas.get(t.value, "ID")   # ¿es palabra reservada?
    return t
  • Las funciones se prueban en el orden en que están escritas. Por eso t_CTE_FLOAT va antes que t_CTE_INT: si no, 3.14 se leería como el entero 3.
  • Las palabras reservadas no tienen regla propia. Se reconocen como ID y se reclasifican con un diccionario.
  • t_error lanza ErrorLexico con el carácter y la línea.

Parser: parser.py

Cada función p_* lleva en su docstring una o varias reglas en BNF. PLY las junta y construye la tabla LALR(1) al importar el módulo.

def p_condicion(p):
    """condicion : IF LPAREN expresion RPAREN body else_opt SEMICOLON
    else_opt  : ELSE body
              | empty"""

def p_empty(p):
    """empty :"""

def p_error(tok):
    raise ErrorSintactico(f"no se esperaba '{tok.value}' (token {tok.type})", tok.lineno)

En esta entrega las funciones no tienen cuerpo porque el parser solo valida. En las entregas 2 y 3 ese cuerpo es donde van las acciones semánticas.
