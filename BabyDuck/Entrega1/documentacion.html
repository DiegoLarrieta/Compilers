1. Herramientas investigadas

En la tarea previa se probaron generadores para C y Go (flex/bison, goyacc y ANTLR). Para el proyecto se cambió a Python, así que se compararon las opciones disponibles para ese lenguaje.

HerramientaAlgoritmoCómo se escriben las reglasA favorEn contra

(Python Lex-Yacc)		LALR(1)En el mismo archivo Python: expresiones regulares en variables t_* y reglas BNF en el docstring de funciones p_*.Mismo modelo que lex/yacc y bison de la tarea previa. Herramienta seleccionada: PLY

  • Conecta con Python sin pasos extra. El scanner y el parser son módulos normales de Python; se corren y se depuran igual que el resto del código.
  • Las entregas siguientes piden puntos neurálgicos. PLY permite ejecutar código al terminar una regla o a la mitad de ella. Con Lark o con los visitors de ANTLR habría que recorrer un árbol después.
  • Es el mismo modelo de la tarea previa. Lo aprendido con flex/bison (tokens, reglas BNF, conflictos shift/reduce) aplica directo.
  • Buena documentación. El manual oficial cubre lex y yacc con ejemplos completos.

El costo que se acepta: la gramática se escribe en BNF puro, y la versión queda fija en ply==3.11 (ver requirements.txt).

2. Cómo se dieron de alta las reglas

Scanner: lexer.py

PLY lee tres cosas del módulo: la lista tokens, las variables t_NOMBRE (expresión regular de un token simple) y las funciones t_NOMBRE (expresión regular en el docstring más una acción).

tokens = ["ID", "CTE_INT", "CTE_FLOAT", "CTE_STRING", "PLUS", ...] + list(palabras_reservadas.values())

t_PLUS = r"\+"          # token simple: solo su expresión regular
t_NE   = r"!="

def t_CTE_FLOAT(t):     # token con acción: convierte el lexema a número
    r"\d+\.\d+"
    t.value = float(t.value)
    return t

def t_ID(t):
    r"[A-Za-z_][A-Za-z0-9_]*"
    t.type = palabras_reservadas.get(t.value, "ID")   # ¿es palabra reservada?
    return t
  • Las funciones se prueban en el orden en que están escritas. Por eso t_CTE_FLOAT va antes que t_CTE_INT: si no, 3.14 se leería como el entero 3.
  • Las palabras reservadas no tienen regla propia. Se reconocen como ID y se reclasifican con un diccionario.
  • t_error lanza ErrorLexico con el carácter y la línea.

Parser: parser.py

Cada función p_* lleva en su docstring una o varias reglas en BNF. PLY las junta y construye la tabla LALR(1) al importar el módulo.

def p_condicion(p):
    """condicion : IF LPAREN expresion RPAREN body else_opt SEMICOLON
    else_opt  : ELSE body
              | empty"""

def p_empty(p):
    """empty :"""

def p_error(tok):
    raise ErrorSintactico(f"no se esperaba '{tok.value}' (token {tok.type})", tok.lineno)

En esta entrega las funciones no tienen cuerpo porque el parser solo valida. En las entregas 2 y 3 ese cuerpo es donde van las acciones semánticas.

Gramática registrada

Esta es la gramática completa tal como PLY la tiene registrada (se obtiene del parser ya construido, no se copió a mano). Tiene 0 conflictos shift/reduce y 0 conflictos reduce/reduce.

programa ::= PROGRAM ID SEMICOLON vars_opt funcs MAIN body END

vars_opt ::= VAR lista_decl
           | ε

lista_decl ::= decl lista_decl
             | decl

decl ::= lista_ids COLON tipo SEMICOLON

lista_ids ::= ID COMMA lista_ids
            | ID

tipo ::= INT
       | FLOAT

funcs ::= func funcs
        | ε

func ::= VOID ID LPAREN params_opt RPAREN LBRACKET vars_opt body RBRACKET SEMICOLON

params_opt ::= lista_params
             | ε

lista_params ::= param COMMA lista_params
               | param

param ::= ID COLON tipo

body ::= LBRACE estatutos RBRACE

estatutos ::= estatuto estatutos
            | ε

estatuto ::= asigna
           | condicion
           | ciclo
           | llamada
           | imprime

asigna ::= ID ASSIGN expresion SEMICOLON

condicion ::= IF LPAREN expresion RPAREN body else_opt SEMICOLON

else_opt ::= ELSE body
           | ε

ciclo ::= WHILE LPAREN expresion RPAREN DO body SEMICOLON

llamada ::= ID LPAREN args_opt RPAREN SEMICOLON

args_opt ::= lista_args
           | ε

lista_args ::= expresion COMMA lista_args
             | expresion

imprime ::= PRINT LPAREN lista_print RPAREN SEMICOLON

lista_print ::= item_print COMMA lista_print
              | item_print

item_print ::= expresion
             | CTE_STRING

expresion ::= exp expresion_resto

expresion_resto ::= op_rel exp
                  | ε

op_rel ::= GT
         | LT
         | NE

exp ::= termino exp_resto

exp_resto ::= PLUS exp
            | MINUS exp
            | ε

termino ::= factor termino_resto

termino_resto ::= TIMES termino
                | DIVIDE termino
                | ε

factor ::= LPAREN expresion RPAREN
         | PLUS operando
         | MINUS operando
         | operando

operando ::= ID
           | cte

cte ::= CTE_INT
      | CTE_FLOAT

programas/factorial.bd

program factorial;
var n, resultado : int;

void calcula(limite : int) [
    var i : int;
    {
        i = 1;
        resultado = 1;
        while (i < limite + 1) do {
            resultado = resultado * i;
            i = i + 1;
        };
    }
];

void saluda() [
    {
        print("Factorial en BabyDuck");
    }
];

main {
    n = 5;
    saluda();
    calcula(n);
    if (resultado > 100) {
        print("grande", resultado);
    } else {
        print("chico", resultado);
    };
    if (n != 0) {
        print("n no es cero");
    };
}
end

$ python main.py programas/error_sintaxis.bd
programas/error_sintaxis.bd: Error de sintaxis (línea 4): no se esperaba ';' (token SEMICOLON)

$ python main.py programas/error_falta_punto_y_coma.bd
programas/error_falta_punto_y_coma.bd: Error de sintaxis (línea 5): no se esperaba 'print' (token PRINT)

En el último caso el ; falta en la línea 4, pero el error se reporta en la línea 5: el parser se da cuenta hasta que lee el siguiente token (print).
